# CIP 样本对齐预检查

> 历史实验记录：保留当时的方案、数据范围和结果。后续进展见 [补充实验报告](三项优化_跨人和视觉补充实验_20261108.md)，当前待办见 [后续工作](ROADMAP.md)。

日期：2026-11-08。仅为离线数据预检查，不涉及训练或模型精度评估。

## 一句话结论

这套数据值得继续研究：能找到六个候选传感器和头部位置，但 **一段动作的传感器文件和位置参考差一行，不能直接按行拼接后训练**。记录条数相同或计数器相同，也不足以证明传感器与位置参考在物理时间上对齐。

## 检查结果

来源：[CIP 官方数据发布](https://zenodo.org/records/6480543)，`MTwAwinda_trials_subject00.zip`，核对官方文件长度与 MD5，并计算本地 SHA-256 `aaeabd37a25f26b2688e38e103eec1e194ec4dec957ce40084e45bff16727666`。数据包分发为 CC BY 4.0；本研究须保留来源和署名。

在一位受试者的两段记录上，仅检查头、骨盆、双手、双脚六个传感器候选文件：

| 记录 | 六个传感器 | 位置参考 | 检查情况 |
| --- | --- | --- | --- |
| 站姿标定 `calibration_npose` | 均为 364 行 | 364 行 | 传感器计数器一致且连续，参考帧序连续；仍不能仅凭行数认定物理同步。 |
| 动作 `sequence_rep2` | 均为 2953 行 | 2954 行 | 传感器计数器一致且连续，参考帧序连续；参考多一行，错位的具体原因未知。 |

六个被检查的文件均标称 60 Hz，四元数模长四舍五入后为 1；只能说明本次抽查未见这些格式问题，不能说明所有数据完整或标定正确。位置表中有 `Head x/y/z`、`Pelvis x/y/z` 字段：原始 `Head z` 数值在标定段约为 1.4888～1.4895，在动作段约为 0.8649～1.4981。这里保留原始量纲，尚未独立确认坐标、地面基准及单位；这些位置来自 Xsens 惯性动捕参考，不是独立光学真值。

上游[数据处理代码](https://github.com/ManuelPalermo/HumanInertialPose/blob/main/hipose/data/dataset_parsing/parse_cip_mtwawinda_dataset.py)对传感器和参考数据进行了标定与截取处理。其做法为理解数据提供线索，并不能单凭代码证明这段样本中首尾哪一帧应该丢弃。需要进一步核对采集流程和同步规则。

## 边界和下一步

- CIP 的位置表是**身体节段位置**，需要核对后才可能映射到 FusionPoser 的关节点；传感器佩戴位置、方向、重力处理和坐标系也必须转换。
- 把参考表中的头部位置拿来当模型输入，只能称为模拟提供头部追踪信息。它不证明仅靠 IMU 能获取头部高度，也可能产生参考信息泄漏，实验设计必须明确说明。
- 当前只有一位受试者，不能做跨人测试；也没有训练新模型或计算新的姿态误差。
- 下一步先对同一动作的传感器和参考序列核实同步方式、单位与坐标，再获取至少不同人的数据，按人分训练和测试。不能根据已查看的测试数据反复调参。

## 本机复现

下面以 `C:\Datasets\CIP\CIP_MTwAwinda_subject00.zip` 为示例，请替换为自己的下载路径。脚本不解压、不运行外部代码，也不上传数据：

```powershell
# 在项目根目录执行
py -3.12 examples/cip_preflight.py 'C:\Datasets\CIP\CIP_MTwAwinda_subject00.zip'
```

脚本独立测试覆盖计数器回绕与缺帧、非法数值、位置表读取与帧号缺口；不能替代对传感器与参考系统物理同步的验证。
