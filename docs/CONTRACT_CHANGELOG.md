# MetaFit 模拟接口契约：版本与兼容规则

> 状态：对 App 团队的**拟议规则**，等待双方确认。当前版本是 `0.3.0-draft`，仅用于本机模拟；字段真相源为 [OpenAPI 契约](openapi.r5-draft.yaml)。版本记录不能证明系统已部署、真实安全或完成 App 联调。

## 从 0.3.0 起的约定

- 在 `0.3.x-draft` 内，维护方不删除已有字段，不改变既有字段、状态码或错误码的含义；涉及安全的行为调整也必须明示，不能悄悄改变。
- 新增可选字段、诊断 warning 等计划提前说明。客户端应忽略未知的可选字段和未知诊断 warning，不得忽略未知安全状态或把它当作安全。**当前响应 schema 使用 `additionalProperties: false`，严格验证的旧客户端可能拒绝新增字段；`status`、`code`、`record_state` 也是闭合枚举。** 因此不能假定新增字段或枚举天然兼容：未经确认，不在 0.3.x 发布会破坏现有客户端的新增值；需要破坏性调整时升 0.4 并给迁移说明。
- 删除字段、改变字段含义、改变已有响应的关键状态码或现有客户端无法安全处理的变化，属于破坏性变更；计划升到 `0.4.0-draft` 或更高，并提供迁移步骤、受影响 fixtures 和通知。供应方尚无机制保证外部团队已收到通知，双方需要确定升级流程。
- 当前仅以文档、人工评审和已有契约测试执行此约定；**尚无自动比较版本间 schema 的兼容性检查或发布门禁**。
- `/meta` 只返回服务自报版本和能力，不能证明契约文件与服务二进制完全一致、服务身份可信或医疗安全。启动时进行版本门禁；不兼容或版本未知时停止普通模拟对接并给用户明确提示。真实 App 的离线提示、紧急处理和升级 UI 需产品与专业负责人审查。

## 已知历史变更

2026-11-08 工程修复：超限 POST 请求仍返回 `413 request_too_large`，连接收尾增加有限的正文丢弃，修复 Windows 上偶发收不到已发送响应的问题。字段、状态码和契约版本保持原约定；复现及回归结果见 [工程改进记录](../CHANGELOG.md)。

| 版本 | 变化与原因 | App 需要做什么 |
|---|---|---|
| `0.3.0-draft` | 已存在会话中，`answer=reported` 若缺少或非法 `question_id`、或带多余字段，从 400 `invalid_request` 改为 400 `safety_report_unattributed`；返回安全提示，**报告未记录**。这改变已有错误码，故按 0.2.x 规则升至 0.3。 | 升级版本门禁，读取 400 body，向用户展示经审核提示，并在正确会话使用符合契约的请求重新报告；参考 `known_session_malformed_reported_answer` fixture。`0.2.2` 的本地有条件通过不自动覆盖此修订。 |
| `0.2.2-draft` | 不存在、失效或标识格式不合法的会话中 `reported` 事件及 `answer=reported` 返回 400 `safety_report_unattributed`，带安全提示、`event_saved=false`，不保存报告；普通未知会话请求仍为 404。 | **这是 0.2.1 → 0.2.2 的安全例外，状态码行为有变化，不能声称完全兼容。** 必须读取 400 body，显示受审安全提示，并在正确会话重新报告；参见 `unknown_session_reported_event` / `unknown_session_reported_answer` fixtures。 |
| `0.2.1-draft` | 修订故障样例、满载 HEAD 和 405/503 声明；此版本已在本地模拟范围有条件验收。 | 该验收不自动覆盖后续 `0.2.2` 修订。 |
| `0.2-draft` | 收敛状态、统一记录语义、补充不适与 HTTP 边界。 | 对照原复审，不能把它等同于当前契约。 |
| `0.1-draft` | 第一版本地接口草案。 | 不能用早期字段/状态假设直接对接当前服务。 |

此前 `0.2.1→0.2.2` 的非兼容安全修订是历史事实；`0.2.2→0.3.0` 按已有规则升级。**当前对接真相源是 `docs/openapi.r5-draft.yaml`**。历史版本材料保存在原项目中。
