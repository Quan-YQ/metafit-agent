# 公开动作数据骨架实验

这次使用卡内基梅隆大学（CMU）公开的动作捕捉数据，先验证“动作数据 → 骨架图 → 模型描述”能否跑通。它是光学动作捕捉数据，不是 IMU 传感器数据。

## 实验材料

- 原始动作：[CMU 22 号人物、14 号动作](https://mocap.cs.cmu.edu/search.php?subjectnumber=22&trinum=14)。CMU 将整段描述为 alternating squats；本实验只抽取其中一小段，不代表对动作质量的专业标注。
- 数据来源：[CMU 动作数据库](https://mocap.cs.cmu.edu/)，其首页说明数据可自由使用。
- 格式转换：使用 Bruce Hahne 的 MotionBuilder 版本 BVH 转换数据，[转换说明与使用条款](https://github.com/una-dinosauria/cmu-mocap/blob/09a07f54f3bbb58797325f009282d0b2048a2871/READMEFIRST.txt)，[原始 BVH 文件](https://github.com/una-dinosauria/cmu-mocap/blob/09a07f54f3bbb58797325f009282d0b2048a2871/data/022/22_14.bvh)。转换说明称该版本不对使用附加限制，并说明它插入了一个人为 T 姿势帧。
- 本地文件 examples/cmu_22_14_sample.bvh：保留骨架结构，抽取原文件从 0 开始计数的第 90、114、138、162、186、210 帧，间隔约 0.2 秒；不包含插入的第 0 帧。源数据采样率约为 120 帧/秒。
- 骨架图：每一列是同一个时刻，上下分别从两个坐标平面观看；从左到右是动作变化。为便于比较，保持统一比例，只去掉人物的水平位移。它是投影图，不等于真人视频。

数据及转换过程可能有误差，图中不可见或互相遮挡的部位不能可靠判断。这个实验不验证动作是否标准、安全或适合某个人。

## 如何运行

在项目目录先做不联网检查：

    py -3.12 examples/check_vision.py --motion-sample

然后运行一次真实读图（会向 DeepSeek 发送生成的骨架图，可能产生费用）：

    py -3.12 examples/check_vision.py --motion-sample --live --ask-key

输入自己的 DeepSeek 密钥，屏幕不会显示输入的字符。不要把密钥发到聊天中。把不含密钥的模型回答、耗时和 token 用量发给协作者即可。模型看到的是六列连续骨架和两个视角；问题不会事先告诉它动作名称。

如果想把图片保存到 examples/cmu_22_14_skeleton.png，可运行：

    py -3.12 examples/render_motion_sample.py

模型输出只用于研究观察；本实验尚未接入原有 Agent 决策链，也不能用作真实训练指导。

## 走路对照实验

为比较不同动作，可使用 CMU 02_01 走路样本。[CMU 的动作目录](https://mocap.cs.cmu.edu/search.php?subjectnumber=2)将该动作标注为 walk；本地样本来自同一 BVH 转换版本的[原始文件](https://github.com/una-dinosauria/cmu-mocap/blob/09a07f54f3bbb58797325f009282d0b2048a2871/data/002/02_01.bvh)。样本保留骨架结构，抽取原文件从 0 开始计数的第 60、84、108、132、156、180 帧，间隔约 0.2 秒。

执行不联网检查：

    py -3.12 examples/check_vision.py --walk-sample

向 DeepSeek 发送走路骨架图（真实调用一次，可能产生费用）：

    py -3.12 examples/check_vision.py --walk-sample --live --ask-key

如需保存图片：

    py -3.12 examples/render_motion_sample.py --walk

对照实验与下蹲实验使用相同提示词，提示词不包含动作名称。骨架图将每一帧的人物水平居中，保留身体姿态变化但不显示实际行进距离。两个样本的动作捕捉对象不同；一次识别正确不能证明识别能力或泛化性能。

## 三个样本的小规模复测

本轮分别发送三张新图，提示词与前两次动作实验相同，不向模型透露样本名称或其他样本的回答。一个命令会连续发送最多三次请求；任何一次出错即停止，不自动重试。每次调用都可能产生费用。

    py -3.12 examples/check_vision.py --final-round --live --ask-key

先做不联网检查可以去掉 --live 和 --ask-key。程序依次输出样本 A、B、C 的回答和 token 用量。请输入自己的密钥，不要把密钥发到聊天中；将三个回答一起提供给协作者，用于人工对照。

样本来源，均由 BVH 格式转换版中从 0 开始计数的第 60、84、108、132、156、180 帧生成：

- A：[23_14](https://mocap.cs.cmu.edu/search.php?subjectnumber=23&trinum=14)，数据库描述为两人交替下蹲中的人物 B；所取片段为下蹲后起身。注意它和前一次 22_14 是同一次双人录制，不能算完全独立的动作来源。[BVH 原始文件](https://github.com/una-dinosauria/cmu-mocap/blob/09a07f54f3bbb58797325f009282d0b2048a2871/data/023/23_14.bvh)。
- B：[02_02](https://mocap.cs.cmu.edu/search.php?subjectnumber=2)，数据库标注 walk；与前一次走路样本是同一个人的另一段录制。[BVH 原始文件](https://github.com/una-dinosauria/cmu-mocap/blob/09a07f54f3bbb58797325f009282d0b2048a2871/data/002/02_02.bvh)。
- C：[111_28](https://mocap.cs.cmu.edu/search.php?subjectnumber=111)，数据库标注 Standing still；实际数据可能有细微晃动。[BVH 原始文件](https://github.com/una-dinosauria/cmu-mocap/blob/09a07f54f3bbb58797325f009282d0b2048a2871/data/111/111_28.bvh)。

这只是小范围探索，不是独立测试集或可靠性评估。图像去掉了每帧的水平位移，不能据此确认实际行进距离或原地踏步；不同视角、遮挡、采样片段、提示词以及模型的不确定性都可能影响结果。不可据此判断动作安全性或向训练者提供指导。
