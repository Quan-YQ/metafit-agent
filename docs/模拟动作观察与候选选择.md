# 模拟动作观察与候选选择

这个独立研究实验把视觉观察和候选选择串联起来。它使用公开动作样本与虚构训练事件，不是 App 接口，也不向训练者展示或投递反馈。

1. R2 先验证模拟事件；报告不适时直接进入安全状态，不处理图片或调用模型。
2. 视觉观察模型分析公开骨架图，输出髋部首尾变化；程序将其与从骨架数据计算的方向对照。不一致、无法判断或输出无效时停止。
3. 研究适配器检查虚构事件与样本绑定，将“视觉模型报告了什么”作为临时模拟事实，交给候选选择模型。视觉模型的自由文本解释不会传给决策模型。
4. 候选选择模型可以提出 `silent`、`notify` 或 `defer`。如提出提醒或延后，实验要求引用该模拟观察；绑定或引用不符时停止。
5. 现有 R3 检查候选结构和引用范围。无论候选是什么，研究输出均保持 `may_display=false`、`delivery=false`。

绑定在决策调用前及返回后分别检查。它只保证本次模拟记录内部一致，不认证身份，也不证明虚构事件和公开动作片段在现实中有关联。R3 引用检查不验证自然语言真实性、模型是否真正理解动作或动作是否安全。图像基准的 5% 阈值仅是工程实验约定。

## 离线运行

在项目目录运行：

    py -3.12 examples/research_motion_choice.py --sample round_a
    py -3.12 examples/research_motion_choice.py --sample squat_1

离线替身使用预设规则：第一条示例产生 `notify`，第二条示例产生 `silent`。这只验证程序可以处理不同选择，**不是对真实模型的行为评估**，也不代表这些提醒应该展示。

## 真实模型实验

在项目目录运行：

    py -3.12 examples/research_motion_choice.py --sample round_a --live --prompt-key

按提示输入 DeepSeek 密钥；输入不会显示。一次运行最多发出两次请求：一次公开骨架图观察、一次筛选后的模拟事实决策。如果第一步失败、观察不一致或绑定有问题，就不会发送第二次请求。失败时不自动重试；可能产生费用，超时后费用也可能未知，以服务商账单为准。不要将密钥发到聊天或保存在项目中。

主要结果：`visual_requests_started` 和 `decision_requests_started` 分别表示已开始的请求数；`candidate_action` 是研究候选动作；`candidate_evidence` 是候选引用的模拟事实编号；`r3_status` 和 `reference_check` 表示结构及引用范围检查；`delivery=false` 与 `may_display=false` 表示没有投递。`decision_estimated_yuan` 只估算文本决策费用，不包含视觉请求，也不是总账单硬上限。

单次真实调用不能证明模型会稳定地产生不同选择。R5 会话安全确认、真实身份、跨设备状态、持久化、App 联调和真实训练指导均不在此实验范围内。

## 复用用户提供的上次观察

一次真实组合实验中，图片观察已成功，但文本模型在模拟自报无不适时使用了仅适用于不适状态未知的固定原因，触发 `none_state_ambiguous_reason`，R3 未运行。该次图片和文本请求均已发起，可能均有费用。

研究客户端现在更明确地提示这两种状态。若结构有效且状态确为模拟自报无不适，而模型恰好使用那句固定原因，客户端会将原因替换成“模拟数据记录为自报无不适，时效及当前状态未确认。”，并输出 `decision_reason_adjustment: none_ambiguous_reason_normalized`；模型的动作、消息和引用不变。原始响应仅保留在进程内供研究核对；未知状态、其他异常和无效引用仍由原规则拦截。修正不证明候选内容真实或安全。

可以复用一次由用户提供、并已记录摘要的 `round_a` 图片观察结果，只请求一次文本选择：

    py -3.12 examples/research_motion_choice.py --reuse-observation --live --prompt-key

复用前会核对本地源文件、图片及问题的摘要；不一致时停止且不调用决策模型。该记录来自用户提供的运行输出，并非本进程独立认证的服务商记录，输出会标记 `visual_replay_origin: user_reported_not_independently_verified`。`prior_reported_visual_usage` 是上次已经产生的图片请求用量，不代表本次新请求；本次 `visual_requests_started` 应为 0、`decision_requests_started` 最多为 1。一次文本请求可能收费，失败不自动重试。
